# 量產與交付作業指南

本文件定義在樣品經使用者確認「風格確定」並寫入 `spec_lock.md` 後，如何補齊剩餘頁面、整備講者備忘錄、執行品質檢查與後處理、匯出原生 PPTX，以及通過檢查腳本驗證後正式交付。

---

## ▋ 一、量產前預估時間告知

在開始大量渲染剩餘頁面之前，Agent 必須先主動告知使用者預估作業時間：
1. **耗時預估標準**：
   - 依據本機實測基準，平均每頁 SVG 撰寫與轉檔約需 5~10 秒。
   - 8 頁簡報約需 1~2 分鐘；20 頁約需 5~10 分鐘；40 頁完整提案約需 15~25 分鐘。
2. **告知訊息格式**：
   > 「風格已鎖定，現在開始為您量產剩餘頁面。本簡報共 [N] 頁，預估量產與匯出約需 [X] 分鐘，請稍候。」

---

## ▋ 二、依鎖定風格補齊剩餘頁面

1. **依據 `spec_lock.md` 延續視覺標準**：
   - 嚴格鎖定樣品階段確立的字級階梯（Hero 42 / Title 34 / Subtitle 24 / Card Title 20 / Body 18 / Caption 14-16）。
   - 底色一致維持淺色底（`#F8FAFC` 或 `#FFFFFF`），主色調（商務藍 `#2563EB`）與深色字（`#0F172A`）。
   - 延續非對稱、無腦三等分卡片牆禁令與標準向量圖示原則。
2. **補齊未繪製頁面與真實性鐵律**：
   - 由主 AI 自己逐頁寫出剩餘頁面的 SVG，**嚴禁派遣子代理**。
   - **投影片文字只能來自中繼稿或使用者檔案，不准補充設備、流程細節、數字、承諾；內容少就用留白（Anchor/Breathing），不要湊字**！嚴禁擅自發明未提及的規格、百分比、時間數字或額外服務承諾。
   - 產出檔案統一存入 `~/b2b-slide-簡報/<日期>-<簡報名>/svg_output/`。
   - 確保檔名依頁序連續命名：`slide_01.svg`、`slide_02.svg`、...、`slide_08.svg`。

---

## ▋ 三、講者備忘錄整備（Speaker Notes）

每一頁簡報皆必須嵌入對應的講者口語提示，方便使用者直接上台報告：
1. **建立總備忘錄檔案**：
   - 於簡報資料夾建立 `notes/total.md`。
   - 內容**嚴格取自 `01-中繼-SSOT.md` 中每一頁的「講者口語提示」**，不擅自發明未提內容。
   - 格式範例：
     ```markdown
     # Slide 1
     你家狗狗一看到外出籠就躲到床底下嗎？

     # Slide 2
     想像一下，你趴在地上拿零食哄牠出來的畫面
     ```
2. **切分逐頁備忘錄**：
   - 執行 ppt-master 備忘錄切分工具：
     ```bash
     ~/.b2b-slide/venv/bin/python ~/.b2b-slide/ppt-master/skills/ppt-master/scripts/total_md_split.py ~/b2b-slide-簡報/<日期>-<簡報名>/
     ```
   - 工具會於 `notes/` 目錄下產生對應各頁的 `slide_01.md`、`slide_02.md` 等檔案。

---

## ▋ 四、品質檢查與 PPTX 匯出後處理

按 ppt-master 主流程依序執行後處理與匯出指令（嚴禁合併或跳步）：

1. **執行 SVG 品質檢查**：
   ```bash
   ~/.b2b-slide/venv/bin/python ~/.b2b-slide/ppt-master/skills/ppt-master/scripts/svg_quality_checker.py ~/b2b-slide-簡報/<日期>-<簡報名>/ --stage final --json
   ```
   確認 0 blocking errors。

2. **產出自包含預覽 SVG (Finalize)**：
   ```bash
   ~/.b2b-slide/venv/bin/python ~/.b2b-slide/ppt-master/skills/ppt-master/scripts/finalize_svg.py ~/b2b-slide-簡報/<日期>-<簡報名>/
   ```
   於 `svg_final/` 產生各頁預覽圖。

3. **匯出原生可編輯 PPTX**：
   ```bash
   ~/.b2b-slide/venv/bin/python ~/.b2b-slide/ppt-master/skills/ppt-master/scripts/svg_to_pptx.py ~/b2b-slide-簡報/<日期>-<簡報名>/
   ```
   匯出檔產出於 `exports/<簡報名>_<時間戳>.pptx`。

4. **建立正式交付檔案**：
   - 將匯出的 PPTX 複製或重新命名為標準交付檔名：
     `~/b2b-slide-簡報/<日期>-<簡報名>/04-<簡報名>.pptx`

---

## ▋ 五、結構驗證與正式交付閘門

在正式回報交付給使用者之前，必須執行驗證腳本：

1. **執行簡報結構檢查**：
   ```bash
   ~/.b2b-slide/venv/bin/python ~/.b2b-slide/scripts/check_pptx.py ~/b2b-slide-簡報/<日期>-<簡報名>/04-<簡報名>.pptx
   ```

2. **執行內容真實性同源檢查（Grounding Gate）**：
   ```bash
   ~/.b2b-slide/venv/bin/python ~/.b2b-slide/scripts/check_grounding.py ~/b2b-slide-簡報/<日期>-<簡報名>/04-<簡報名>.pptx ~/b2b-slide-簡報/<日期>-<簡報名>/01-中繼-SSOT.md
   ```

3. **交付通行條件**：
   - `check_pptx.py` 必須回傳 **exit 0**（每頁至少 1 個可編輯文字框、講者備忘錄非空、0 筆整頁貼皮圖片）。
   - **交付前必跑 check_grounding.py 且必須 exit 0**（所有投影片文字與數字 100% 同源於中繼稿，無未授權的捏造細節或數字）。
   - 若有任何錯誤，必須修正後重新匯出與驗證，嚴禁將未通過之檔案交付使用者。

4. **完成交付回報**：
   - 回報簡報檔案完整路徑：`~/b2b-slide-簡報/<日期>-<簡報名>/04-<簡報名>.pptx`。
   - 回報總頁數與驗證通過狀態。
