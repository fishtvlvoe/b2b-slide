## Context

老魚目前做商務簡報的實際流程散在 4 個本機工具：kimi-slide（中繼 md + Kimi 提示詞）、簡報師 agent（三選一路由）、簡報大師 Dashi（HTML 簡報）、ppt-master（原生 PPTX）。某公關行銷公司 14 頁提案證明「中繼 Markdown → ppt-master → 原生 PPTX」這條路可以做出顧問級成品，但流程只存在老魚的電腦和腦袋裡，學生無法自己跑。

規格來源是本 repo 根目錄的 5 份文件：`AGENTS.md`（專案定位）、`01-CORE-METHODOLOGY.md`（破例感官與四步法）、`02-INTERVIEW-ENGINE.md`（訪談狀態機與 8 切角）、`03-PRESENTATION-SPEC.md`（去 AI 味與字級階梯）、`04-CASE-PR-AGENCY-AND-BNI.md`（黃金案例）。

限制：
- ppt-master 必須在使用者電腦執行 Python；它的瀏覽器預覽開在 `localhost`，雲端或聊天網頁版 AI 無法提供。
- ppt-master 上游（github.com/hugohe3/ppt-master）有改寫過 git 歷史：作者本機實測的版本（`v4.5.0-38-g4e6ecbcb`）的 commit 不在上游任何分支上，學生無法下載到同一份，只能鎖上游正式 tag。上游目前 47 個 tag，最新 `v6.7.0`（2026-10-08），`v4.5.0` 仍存在。
- 本機只有 macOS 可實測，Windows 只能靠學生試裝回報。

## Goals / Non-Goals

**Goals:**

- 學生複製一句話貼給 Claude 電腦版 App（或執行一行指令），就能裝好並開始做第一份商務簡報。
- 換 Claude Code、Codex CLI、Gemini CLI 都走同一套流程，產出品質靠流程與規格約束，不靠模型品味。
- 每份簡報都經過：訪談 → 中繼 Markdown 拍板 → HTML 故事地圖 → 5 頁樣品批註 → 完整 PPTX。
- 支援 4 種對外商務簡報：客戶提案、BNI 專題、公司／產品介紹、合作邀約。

**Non-Goals:**

- 內部報告（月報、專案進度）：四步法第 4 步不適用，需另一套訪談題，留到第二版。
- 課程簡報：目前學生不需要。
- Kimi PPT 提示詞輸出、簡報大師 HTML 簡報、簡報師三選一路由：全部移除，只留 ppt-master。
- 網頁版 AI、一般聊天模式、雲端 AI（Claude Code 網頁版、Codex 雲端）：預覽批註頁無法使用，不支援。
- 一鍵生成：任何階段都不允許跳過訪談直接產出整份簡報。
- 修改 ppt-master 原始碼：只呼叫它，不 fork、不改。
- 把 ppt-master 預覽編輯器介面翻成繁體（2026-10-10 老魚定）：介面只有簡體／英文／日文；本機安裝的工具每次更新都會覆蓋修改，每次都得重做，不是長久做法；簡體對學生影響不大，維持原樣。
- 在預覽編輯器內上傳圖片：ppt-master 沒有上傳功能（只能看、點選、批註、改文字與位置）；學生要放照片，改成把照片拖進 AI 對話框，由 AI 存進簡報資料夾並排進頁面，此流程在任務 6.2 實測。

## Decisions

### 只用 ppt-master 一個渲染工具

**為什麼**：一個工具代表樣品與成品同源，使用者在樣品階段看到的就是最後拿到的樣子；ppt-master 已內建瀏覽器確認頁（`confirm_ui`）與預覽編輯器（`svg_editor`），不需要另外接 HTML 工具。
**被否決**：(a) Kimi 提示詞：要使用者自己貼到 Kimi，出不了原生 PPTX；(b) 簡報大師：輸出主體是 HTML 簡報；(c) open-slide 做樣品、ppt-master 量產：兩個工具之間要翻譯風格，顏色字體會對不上。

### 5 頁樣品批註後才量產

**為什麼**：ppt-master 要整份畫完才能預覽，40 頁方向錯了要整份重畫；先做 5 頁（每頁不同版型：圖表式、分類式、對照式、時間軸、定錨大字）讓使用者挑風格、改顏色字體位置、放自己的照片或 SVG icon，1~2 輪定案後鎖進 ppt-master 的 `spec_lock.md`，再量產剩下的頁。
**被否決**：直接量產再改（成本高）；只看 HTML 故事地圖不看樣品（看不到視覺風格）。

### HTML 故事地圖放在中繼 Markdown 拍板之後、樣品之前

**為什麼**：終端機只能看文字，使用者很難在腦中排出 20~40 頁的順序；故事地圖只畫「每頁講什麼、屬於四步法哪一段、頁面節奏（Anchor／Dense／Breathing）」，1 分鐘就能產出，用來先抓順序錯誤。檔案存到使用者電腦並用預設瀏覽器開啟，淺色底、無 Emoji、SVG 圖示。
**被否決**：跳過故事地圖（順序錯誤要到樣品階段才發現）。

### 訪談引擎沿用 writing-assistant 的一題一問與破例感官

**為什麼**：`~/.claude/skills/writing-assistant` 已驗證過一題一問、名詞＋動詞追問；本案改寫成商務版，加入 5 階段狀態機、8 切角題庫、四步法第 4 步的 4 種簡報類型變體。改寫後的內容放進本 repo，不引用老魚本機路徑，因為學生電腦沒有這些檔案。
**被否決**：從零寫新題庫（重工）；直接引用本機 skill（學生裝不到）。

### 訪談採 grilling 方式：建議答案只用學生自己的話

**來源**：github.com/mattpocock/skills 的 `grilling`（MIT，2026-10-09 版本）。原版五個核心：決策樹、一輪問一批（frontier）、每題附建議答案（回答「對」即接受）、事實自己查只把決定交給人、講不清楚的先做出來看（prototype）。
**採用方式**：
- 第二題起每題附一個建議答案（➡️），只能用學生在本份簡報講過的話或丟進來的文件組成，不准加入新的事實、數字、名字；第一題不附建議；沒有素材可用時不附建議。
- 每階段結束出摘要，學生至少要改一個字或補一句才往下走；單純回「對／好」會被追問要改哪裡。原版文件自己點出的最大風險就是使用者一路點頭、最後拿到 AI 寫的計畫，這條規則就是用來防這個。
- 學生丟進來的檔案（公司簡介、報價單、逐字稿）先讀，查得到的欄位不再問，改成建議答案讓學生確認。
- 依回答跳題：簡報類型決定第 5 階段題目；已從檔案取得的欄位跳過。
- 「講不清楚的先做出來看」對應既有的 5 頁樣品流程，不另加機制。
**為什麼**：只開放問題，不擅長表達的學生會卡住；建議答案限定只能用學生自己的素材，就能保留原本「不讓 AI 代替學生思考」的原則（`docs/規格/02-INTERVIEW-ENGINE.md` 第二條）。
**被否決**：(a) 每題都給 AI 自編的建議答案：學生會被帶走，違反原則；(b) 完全不給建議：卡關學生沒有出路。

### 預設一次一題，學生可切換成一輪一批

**為什麼**：學生多為商務人士，一次讀 3~5 題容易跳著看、隨便答；原版 grilling 文件也明列「一次一題」是官方支援的做法，適合閱讀較慢或需要專注的人。學生說「快一點／一次問完」就切換成一輪一批（每題編號、各自附建議答案、同一輪不放互相依賴的題目），可隨時切回。
**被否決**：預設一輪一批（來回次數少，但學生負擔重、容易隨便答）。

### 四步法第 4 步依簡報類型換說法

| 簡報類型 | 第 4 步問法 |
|---|---|
| 客戶提案 | 下一步要對方做什麼決定、拍板條件是什麼 |
| BNI 專題 | 誰是理想引薦對象、別人一句話怎麼介紹你 |
| 公司／產品介紹 | 什麼樣的客戶最適合、他們會在什麼情境想到你 |
| 合作邀約 | 想找什麼樣的夥伴、合作後雙方各得到什麼 |

**為什麼**：4 種都是「對外、希望對方採取行動」，前 3 步完全共用，只有收尾不同。

### 學生只拿 b2b-slide 一個 repo，ppt-master 安裝時自動下載並鎖定上游 tag

**為什麼**：ppt-master 本機複製一份 1.4GB，塞進 repo 會讓 GitHub 上傳卡住、更新困難；分開放，學生只記一個網址。鎖定上游正式 tag，避免作者改版後學生裝不起來。
**鎖哪一版**：候選 `v4.5.0`（最接近某公關行銷公司實測版本）與 `v6.7.0`（最新）。由任務 1.1 用同一份 BNI 案例中繼稿各跑一次，以「能產出 PPTX、文字框可編輯、每頁有講者備忘錄、`confirm_ui` 與 `svg_editor` 能開」為準選定，選定結果寫進 `ppt-master.lock`。
**被否決**：整包放進 repo；每次抓最新版。

### 安裝靠「AI 讀說明書」而非寫死兩套腳本

**為什麼**：學生 macOS 與 Windows 都有。寫一份給 AI 讀的 `INSTALL-FOR-AI.md`，讓 Claude 自己判斷作業系統、檢查 Python 與 git、下載 ppt-master 鎖定版、安裝依賴、跑自我測試；終端機使用者另有 macOS 的 `install.sh` 一行指令與 Windows 的 `install.ps1`。
**被否決**：只支援 macOS（學生有 Windows）。

### 學生的工作資料夾與開發檔案分開

**為什麼**：repo 根目錄有給開發者用的 Spectra 設定（`CLAUDE.md` 的 SPECTRA 區塊、`.claude/skills/spectra-*`），若學生直接在 repo 裡工作，學生的 AI 會讀到這些開發指令而混亂。安裝程式把工具放在 `~/.b2b-slide/`（隱藏，含 repo 與 ppt-master），另外建立學生的工作資料夾 `~/b2b-slide-簡報/`，裡面只有給學生 AI 讀的入口檔（`AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 指向同一份流程）與每份簡報的子資料夾。
**被否決**：學生直接在 repo 裡工作。

### 安裝頁用 GitHub Pages

**為什麼**：repo 已公開，GitHub Pages 不需另外的主機或帳號，網址固定為 `https://fishtvlvoe.github.io/b2b-slide/`。
**被否決**：Cloudflare Pages（多一套部署設定，目前沒有必要）。

### 舊簡報師 repo 只標示停用

**為什麼**：`Awesome-slides-master` 已公開、有既有安裝指令；只改 README 開頭為停用說明並指向 b2b-slide，不刪 repo，避免舊連結失效。

## Implementation Contract

**使用者看得到的行為：**

1. 安裝：學生在 Claude 電腦版 App 的 Code 分頁貼上安裝頁提供的一句話；AI 讀 `INSTALL-FOR-AI.md` 完成安裝，最後輸出一行「安裝完成：ppt-master <tag>、Python <版本>、自我測試通過」，或在失敗時輸出卡在哪一步與下一步該做什麼（例如「沒有 Python，請到 python.org 下載 3.10 以上」）。
2. 開始：學生在工作資料夾說「我要做商務簡報」，Agent 先問簡報類型（4 選 1，開放回答，由 Agent 判斷歸類），之後每則訊息只問 1 題。
3. 訪談 5 階段：核心結論 → 破題鉤子 → 現狀問題與肉身場景 → 執行解法與交付標準 → 第 4 步（依類型）。回答出現抽象形容詞時，Agent 用名詞＋動詞追問；回答模糊時換 8 切角中尚未用過的一角追問；同一階段追問上限 3 次，第 3 次後用目前資訊整理並請使用者確認，避免無限追問。
4. 中繼 Markdown：每份簡報一個子資料夾 `~/b2b-slide-簡報/<日期>-<簡報名>/`，產出 `01-中繼-SSOT.md`，結構照 `02-INTERVIEW-ENGINE.md` 第四節（核心定位 + 逐頁規劃），每頁標註四步法段落與節奏類型。必填欄位缺漏時 Agent 不得往下走。使用者明確說「確認」才進下一階段。
5. 故事地圖：產出 `02-故事地圖.html` 並開啟瀏覽器，終端機同時列出純文字版頁序，供無法開瀏覽器時使用。
6. 樣品：產出 `03-ppt-master-交接包.md`（中繼稿 + 風格規格 + 5 頁樣品清單），呼叫 ppt-master 產出 5 頁，啟動 `svg_editor` 預覽並給出 `localhost` 網址；使用者在預覽頁直接改或寫批註，Agent 讀回批註修改；使用者說「風格確定」後寫入 `spec_lock.md`。
7. 量產與交付：依鎖定風格產出完整頁數，跑 ppt-master 品質檢查，匯出 `04-<簡報名>.pptx`（原生可編輯、每頁講者備忘錄），回報檔案路徑與頁數。

**資料形狀：**

- `ppt-master.lock`：一行 `tag=<上游 tag>`，安裝程式與 Agent 都從這裡讀版本。
- `01-中繼-SSOT.md` 必填欄位：簡報類型、核心主張、破題鉤子、第 4 步內容（依類型）、逐頁規劃（每頁：頁碼、標題一句話結論、四步法段落、節奏類型、內容重點、講者口語提示）。

**失敗模式：**

- Python 不存在或版本低於 ppt-master 要求：安裝停止，告訴使用者下載位置，不自動用系統管理員權限安裝。
- ppt-master 下載失敗（沒網路、GitHub 擋）：安裝停止並說明，不留下半套安裝。
- `localhost` 預覽打不開：Agent 改用匯出 PNG 預覽圖讓使用者看，批註改用文字回覆。
- 使用者要求「直接幫我生成整份」：Agent 說明本工具不做一鍵生成，回到目前訪談階段。

**驗收方式：**

- 用 `04-CASE-PR-AGENCY-AND-BNI.md` 的 BNI 案例當使用者回答腳本，完整跑一輪，產出 `01-中繼-SSOT.md`、`02-故事地圖.html`、5 頁樣品、完整 `.pptx`，存一份到 `~/Downloads/b2b-slide-驗收/`。
- 用 `python-pptx` 讀回 `.pptx`：每頁至少 1 個可編輯文字框、每頁 `notes_slide` 非空、沒有整頁圖片。
- 訪談逐字稿檢查：Agent 每則訊息問號數 ≤ 1（技術說明的反問除外）。
- 在全新使用者帳號或空的家目錄模擬安裝一次，確認不依賴老魚本機路徑（`grep -r "/Users/fishtv"` 在 repo 內 0 筆，Spectra 開發設定除外）。

**範圍：**

- In scope：上述 7 項行為、安裝說明書與兩支安裝腳本、安裝頁、舊 repo 停用說明、驗收案例。
- Out of scope：內部報告與課程簡報、Kimi／簡報大師輸出、網頁版 AI、修改 ppt-master、上架到 skill 市集、多人協作、付費機制。

## Risks / Trade-offs

- [ppt-master 上游改版或刪 tag] → `ppt-master.lock` 鎖 tag；安裝失敗時訊息附上 tag 名稱，老魚改 lock 一行即可更新。
- [選定的 tag 行為與某公關行銷公司實測版本不同] → 任務 1.1 用 BNI 案例實測兩個候選 tag 再選，不憑推測。
- [Windows 無法本機實測] → 上課前請 1 位 Windows 學生照安裝頁試裝，回報結果寫進 `docs/windows-試裝紀錄.md`；這是推測風險，目前未驗證。
- [Codex、Gemini CLI 不會自動讀 skill] → 學生工作資料夾同時放 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`，內容都是「讀 `~/.b2b-slide/agent/流程.md` 並照做」；Codex 與 Gemini 實測列為驗收項，未測前標 unverified。
- [不同模型不遵守一題一問] → 流程檔把規則寫成每回合自我檢查清單；驗收時檢查逐字稿問號數。
- [ppt-master 單份簡報耗時長（40 頁估計 30~60 分鐘，未實測）] → 5 頁樣品先行，量產前告知預估時間；任務 1.1 實測時記錄實際耗時。
- [學生電腦沒有 git] → 安裝說明書先檢查 git，沒有時改用下載 zip。

## Migration Plan

新專案，無資料搬移。上線順序：本機完成並驗收 → 建立公開 GitHub repo 並推送（需老魚同意後才執行）→ 開啟 GitHub Pages → 更新舊簡報師 repo README。回滾：GitHub repo 設為私人即可停止提供。
